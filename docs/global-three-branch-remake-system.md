# Global Four-Branch Remake System

本文件沉淀复刻 / 原型重构系统的四条交付支线通用规则。它不绑定某一种题材，可用于角色动作、产品广告、文旅空间、建筑、汽车、食物、UI、卡通、怪物、超现实短片，以及已有视频提示词的二次重构。

## 1. 通用前置规则

在选择 A/B/C/D 线之前，必须先完成后台 DNA 拆解和审核：

- 剧情功能和情绪曲线
- 镜头数量、镜头顺序、切点节奏
- 运镜、角度、构图、镜头质感
- 主体出场、身份确认、表演节拍
- 台词 / 旁白功能和时机
- 道具 / 工具 / 机制触发
- 群体或环境反应
- 变身、展开、损坏、激活、完成等状态变化
- VFX 触发、扩散、回拉、升级和终态
- 音效、BGM、字幕和后期边界
- 最终 payoff 和尾部可读时间
- 如果输入是已有提示词，还必须拆出提示词结构、变量、不变量、可替换层、模型语法、负面词和字数/时长约束
- 出词前必须完成 A11 评分，低于 95/100 不得交给用户。

最终模型提示词只描述新片本身，不写“参考片、原片、学习、复制、后台分析、原始提示词、照着这段提示词改”等过程语言。

## 2. A 线：资产直出

A 线用于用户提供资产、要求资产一致，或身份 / 产品 / 场景 / 道具稳定性优先的复刻重构。

核心模型：

```text
身份资产 -> 环境资产 -> 道具/机制资产 -> 执行态资产 -> 最终 payoff 资产
```

资产设计规则：

- 每张上传图只承担一个窄职责。
- 身份资产保持静态干净，只锁脸、轮廓、产品形状、服装 DNA、品牌物、载具形态、材质系统或生物结构。
- 执行态资产只表达一个允许状态，例如变身中、产品展开、手部交互、撞击态、破损态、UI 激活态、食物切开态、车辆漂移动作等。
- 最终 payoff 资产必须单独设计，只允许在最终镜头出现，例如最终法相、产品 hero reveal、品牌揭示、完成变身、爆炸花、群众揭示、地标揭示、成品菜、完成 UI 状态。
- 多状态板可以用于人审，但不要直接上传给 Seedance，除非你真的想让多个状态同时出现在画面中。
- 不要默认用关键帧解决时点问题；关键帧可能泄漏到错误镜头。优先使用资产权限和时间权限语言。
- 单条 12-15 秒 A 线无法同时保住快节奏和资产一致时，应拆成多段生成再剪辑。

提示词写法：

- 先写上传顺序和资产权限。
- 使用 `@图片X 只锁身份`、`@图片Y 只允许用于 SH06`、`@图片Z 不得在 SH08 前出现`、`不要把该资产渲染成第二主体` 这类权限语句。
- 写镜头职责，而不只是画面描述：引入、确认、触发、反应、变化、冲击、揭示、收束。
- 状态变化必须写成过程：`变化前状态 -> 外力或内力作用 -> 材质/身体/物体/机制变化 -> 新状态稳定`。
- 负面词按当前类型定制，不把玄幻、产品、建筑、食物、UI、卡通的失败项混贴。

A 线基准：

- 当前系统把 86/100 作为有资产复刻的最低可用视觉基准。
- 交付提示词应按 95/100 标准自审。
- 如果资产稳定但时间整体后移，不默认继续加图；先减少资产、隔离职责、强化时间权限，仍失败时拆段。

## 3. B 线：故事板控制

B 线用于镜头顺序、切点节奏、动作方向、构图重心和空间调度优先的复刻重构。

故事板规则：

- Seedance 只接收干净黑白手稿故事板或干净控制帧。
- 不上传带箭头、标签、编号、文字、彩色标记、标题栏、UI 边框或白底资产板痕迹的故事板。
- 参考片有 8 个镜头，就设计 8 格或 8 张干净控制帧，不强行变成 12 格。
- 超过 10 镜必须拆成多个故事板或多个 Seedance 段落。
- 带标注故事板只用于人审，Seedance 使用无标注版本。
- Seedance 提示词必须说明故事板只锁镜头顺序、构图、运动方向和切点节奏，不渲染边框、编号、箭头、文字或面板布局。

可复用表述：

```text
将提供的 [clean board name] / [grid size] / SH01-SH08 制作成一段流畅的电影级动画视频。严格保持 SH01-SH08 的镜头顺序、切点节奏、构图重心、动作方向和镜头连贯性。不要渲染故事板边框、编号、箭头、文字标注或面板布局。故事板只作为运动、构图、镜头切点和动作方向参考，最终必须是一条连续成片。
```

B 线常见失败：

- 箭头、标签、编号或面板 UI 被渲染进画面。
- 成片变成故事板翻页或网格。
- 角色身份跟随草图而不是资产图。
- 切点节奏变成慢推慢摇。
- 提示词和控制图过多，互相污染。

最佳实践：

- 需要身份稳定时，用 A 线资产 + B 线干净故事板。
- 身份参考和运动参考必须分开写。
- 如果故事板压过角色资产，将故事板简化成黑白剪影，并强化资产身份权限。

## 4. C 线：纯文本直出

C 线用于用户只给片段、短片或链接，没有资产和故事板，或明确只要一条 Seedance 提示词快速测试方向。

C 线规则：

- 无 `@` 引用、无上传图片、无资产、无故事板。
- 提示词通常控制在用户要求的长度内，常见为 2500 中文字以内。
- 短不等于虚，每句话都要控制剧情功能、镜头时机、运镜、表演、状态变化、VFX、声音或失败预防。
- 负面词只写纯文本生成风险：镜头数不足、一镜到底、近脸延后、口型缺失、状态变化缺失、触发点缺失、最终态提前、身份漂移、道具漂移、坏手、风格漂、字幕文字等。
- 不写 A/B 线的资产板、故事板、箭头、面板、`@` 引用逻辑，除非用户真的提供了这些输入。
- 用因果锁，不只用时间锁。过度激进的时间闸门会导致顺序混乱或最终态提前。

C 线因果模型：

```text
入场/建立 -> 身份/表演/台词节拍 -> 道具/工具/机制触发 -> 环境/群体反应 -> 状态变化 -> 触发/冲击 -> 最终 payoff
```

C 线交付前自检：

- 纯文本，无 `@` 引用。
- 不出现源片、学习、复制等语言。
- 符合字数限制。
- 镜头职责齐全。
- 状态变化明确。
- 最终 payoff 存在且有尾部时间。
- 不生成后期字幕和 BGM。

## 5. D 线：已有提示词重构

D 线用于用户已经拿到一段视频生成提示词，例如 12-15 秒 Seedance / Kling / Sora / 图生视频提示词，希望基于这段提示词做复刻、改编、变量替换或原型重构。

D 线和 C 线不同：

- C 线的输入源是片段、短片或链接，没有资产和故事板。
- D 线的输入源是一段已有提示词。提示词本身就是原型，需要先拆 prompt DNA。

D 线前置流程：

```text
原始提示词
-> prompt_source_lock
-> prompt_dna_ledger
-> invariant_map / variable_map
-> replaceable_layer_options
-> 用户选择替换范围
-> 至少 3 个重构方向
-> 选定方向后改写最终提示词
```

提示词 DNA 必须拆：

- 时长、画幅、模型语法、语言、字数或平台约束。
- 镜头数量或隐含 beat 数。
- 故事结构、开场方法、转折、爆点、结尾 payoff。
- 角色身份、角色功能、动作状态、服装、表情、台词/旁白功能。
- 场景地理、时间天气、光源、前中后景、空间锚点。
- 道具、产品、法术、VFX 或机制触发链。
- 运镜、景别、切点节奏、运动方向、速度曲线、构图重心。
- 连续性模式：硬切、多段拼接、伪一镜到底、真实一镜到底、第一人称手持跟拍、固定机位、屏幕录制或幻灯片。时间码动作点不等于镜头切点。
- 风格、媒介、色彩、材质、光影、质感、负面词。
- 声音、台词、字幕、BGM 和后期边界。

可替换变量：

- 风格替换：媒介、类型、色彩、光影、时代、镜头质感。
- 元素替换：道具、产品、法术核心物、UI、食物、车辆、建筑、生物、环境元素。
- 角色替换：主角身份、年龄、职业、物种、服装、动作语言、力量来源。
- 场景替换：地点、地理、天气、时代、文化语境、空间尺度。
- 台词/旁白替换：台词功能、语气、节奏、语言，不默认生成字幕。
- 剧情替换：设定、冲突、反转、终帧 payoff。
- 镜头替换：镜头数、切点、运镜路径、景别推进和节奏密度。

不变量锁定：

- 片长与节奏结构。
- 镜头功能和因果顺序。
- 连续性模式。如果提示词写了第一人称手持、镜头随主体自然跟随、操作者呼吸感、自动对焦搜索、自动白平衡漂移等，默认锁为一镜到底手持跟拍，不得改写成 SH 硬切，除非用户明确要求剪辑版。
- 主体出场、触发、变化、冲击、终帧的功能链。
- 用户要求保留的风格、角色、场景、台词或镜头层。
- 必要负面约束，例如无字幕、水印、随机文字、坏手、一镜到底、镜头数不足。

D 线需求收集：

用户没有明确说明时，必须先问或给选项，让用户选择替换范围：

- 只替换风格。
- 只替换元素 / 道具 / 产品。
- 只替换角色。
- 只替换场景。
- 只替换台词 / 旁白。
- 替换剧情，但保留镜头节奏和运镜。
- 全量原型重构。

D 线方向门禁：

- 除非用户已经指定唯一方向，否则必须给至少 3 个重构方向。
- 每个方向必须写清：方向名、保留的不变量、替换的变量、新角色、新场景、新道具/产品/机制、新台词功能、风格、风险和推荐支线。
- 用户选择方向后，才输出最终可复制提示词。

D 线交付前自检：

- 没有把原始提示词机械同义改写。
- 没有把原始提示词里的时间码动作点误判为硬切镜头。
- 连续性模式、时间码功能、相机路径、表演动作、空间调度、道具机制、声音和终帧骨骼都已命名。
- 改写是在原提示词语法内部完成的：优先调整变量、动作因果、beat 文案和场景锚点，不靠堆叠外挂式负面词或新增物理规则硬压。
- 变量和不变量清楚分开。
- 最终提示词只描述新片本身，不出现“原始提示词、参考提示词、照着改、不要复制”等过程语言。
- 如果用户后续加入资产，升级到 A 线；如果加入故事板，升级到 B 线；如果只要无资产文本成片，保持 D 线文本重构。
- A11 评分达到 95/100；低于 95 必须回炉，不交付。

## 6. 分支选择

- 身份、产品、道具或场景一致性最重要：选 A 线。
- 镜头顺序、切点节奏、构图方向最重要：选 B 线。
- 没有资产，只想快速拿一条 Seedance 提示词：选 C 线。
- 用户提供已有提示词，并希望替换风格、元素、角色、场景、台词、剧情或镜头变量：选 D 线。
- 身份和镜头节奏都重要：选 A+B。
- 提示词重构后又需要资产稳定：选 D+A。
- 提示词重构后又需要故事板控制：选 D+B。
- 单条 12-15 秒无法兼顾快节奏和复杂状态：拆段生成再剪。

## 7. 跨支线经验

- 不要用堆字解决所有问题，先判断失败类型：资产漂移、时间漂移、状态漏项、最终 payoff 太短、源片语言泄漏、故事板污染或节奏崩塌。
- 不要把提示词重构做成同义词替换；D 线必须先判断哪些层能替换、哪些层要保留。
- 不要为了修结果给提示词外挂一堆原 prompt 没有的硬约束；先在原 prompt 的变量、动作、关系、事件和连续性表达里修。
- 不要用更多关键帧解决所有时间问题，关键帧也会泄漏。
- 不要把多状态图作为视频输入，除非想同时展示多状态。
- 始终分离身份、动作状态和最终 payoff。
- 台词和字幕要分开，台词可以是口型/声音表演，字幕默认不生成。
- 后期 BGM 不进入 Seedance；只写 `无BGM` 和必要 SFX。
- 最终提示词不是分析记录，而是一个新独立短片的生产命令。

## 8. 最低交付标准

任何复刻 / 重构系统输出都必须：

- 标明 A/B/C/D 或混合支线。
- 写清上传 / 输入逻辑。
- 保留参考片或原始提示词的功能镜头数量、beat 顺序和因果结构。
- 后台明确变量和不变量。
- 如果输入是已有提示词，必须输出 prompt DNA 和可替换层。
- 交付 source-free 的模型提示词。
- 交付前执行 prompt lint。
- 交付前执行 A11 评分，低于 95/100 不得发布给用户。
- 测试结果要用证据图、切点和失败类别评分，不能用泛泛感受修提示词。
